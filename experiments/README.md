# Benchmark functions and experiments

This directory holds the ML functions the paper profiles, plus the notebooks
that reproduce its figures. Nothing here is part of the `optiserve` library —
the library only ever *talks to* functions that are already deployed.

## What you need before deploying

| | |
|---|---|
| **AWS credentials** | On the standard chain: environment variables, a `~/.aws/credentials` profile, or an instance role. There is no `.env` file — neither the library nor the templates read one. |
| **AWS SAM CLI** | `sam build` / `sam deploy`. |
| **Docker** | All three functions are container-image Lambdas (`PackageType: Image`). |
| **An IAM role that already exists** | See below. SAM will *not* create it. |

### The execution role

Each `template.yaml` sets `Role:` explicitly rather than letting SAM synthesise
one from `Policies:`, so the role must exist in the account you deploy into. Its
ARN is assembled at deploy time:

```yaml
Role: !Sub "arn:${AWS::Partition}:iam::${AWS::AccountId}:role/${LambdaExecutionRoleName}"
```

`${AWS::AccountId}` is a CloudFormation pseudo-parameter — it resolves to
whichever account your credentials belong to, which is why no account id is
committed here. `LambdaExecutionRoleName` defaults to `lambda-role`; override it
if yours is named differently:

```bash
sam deploy --parameter-overrides LambdaExecutionRoleName=my-execution-role
```

The role needs, at minimum:

- `AWSLambdaBasicExecutionRole` — CloudWatch Logs. **Required**: OptiServe reads
  every measurement out of the function's log group.
- X-Ray write permissions — the templates set `Tracing: Active`.
- `s3:GetObject` on the model bucket, for `bert` only (it loads weights from S3
  at cold start).

## Deploying

```bash
cd experiments/functions/resnet   # or yolo, or bert
sam build
sam deploy
```

Stacks are named in each `samconfig.toml` (`sam-resnet`, `sam-yolo`,
`sam-bert`), deploying to `us-east-1` by default. Each stack outputs the
function ARN and an API Gateway URL.

## Selecting a model variant — the three functions differ

This matters for profiling, because OptiServe switches variants by rewriting the
function's `MODEL_NAME` environment variable
(`ConfigManager.set_config(model_name=...)`).

| function | how the variant is chosen | works with `optiserve profile --models`? |
|---|---|---|
| `resnet` | `os.getenv("MODEL_NAME")` | yes |
| `yolo` | `os.getenv("MODEL_NAME")` | yes |
| `bert` | `event["model_name"]` — from the **request payload** | **no** |

`bert` also reads `S3_BUCKET` (defaulting to a bucket name hardcoded in
`app/app.py` that you will not own) and fetches `{model_name}/pytorch_model.bin`
from it. To profile `bert` per variant you have to either point `S3_BUCKET` at
your own bucket and drive the variant through `--payload`, or change
`app/app.py` to read `MODEL_NAME` the way the other two do.

Variants that have been profiled, judging by the `.mdl` cache the evaluation
expects:

- `resnet` — `resnet-18`, `resnet-34`, `resnet-50`, `resnet-101`, `resnet-152`
- `yolo` — `yolov10n`, `yolov10s`, `yolov10m`, `yolov10l`
- `bert` — `bert-base-uncased`, `distilbert-base-uncased`, `distilgpt2`

## Profiling a deployed function

```bash
optiserve profile \
  --function resnet --yes \
  --region us-east-1 \
  --models resnet-18 resnet-50 resnet-101 \
  --memory-min 2048 --memory-max 10240 \
  --checkpoint-dir output/checkpoints \
  --output-dir modeled_functions
```

`--yes` is required: profiling repeatedly rewrites the live function's
`MemorySize`, `Timeout` and `MODEL_NAME`, and invokes it hundreds of times.
The original configuration is restored on every exit path, including a crash or
`Ctrl-C`. Use `--checkpoint-dir` so an interrupted run resumes rather than
paying for the same invocations twice.

Select an AWS profile with the standard `AWS_PROFILE` environment variable.

## Notebooks

The `*.ipynb` files reproduce the paper's figures from the profiled models and
the CSVs under `perf_cost_data/` and `opt_curve_data/`. They expect the
`modeled_functions/*.mdl` cache to be present; that cache is gitignored and can
only be regenerated by profiling against live AWS.
